# Security Policy

## Reporting Security Vulnerabilities

If you discover a security vulnerability in GlimWorld, please **do not** open a public GitHub issue. Instead, please report it responsibly by emailing the project maintainers directly.

### How to Report

1. **Email**: Send a detailed report to the repository owner
2. **Information to Include**:
   - Description of the vulnerability
   - Steps to reproduce the issue
   - Potential impact
   - Suggested fix (if you have one)

We appreciate your responsibility in disclosing vulnerabilities and will work with you to address the issue promptly.

## Security Considerations

### For Users

- Keep your browser and operating system updated
- Enable security features in your browser
- Be cautious when opening files or following external links from untrusted sources
- Report any suspicious activity to the maintainers

### For Contributors

- Never commit sensitive information (API keys, tokens, passwords)
- Use `.gitignore` to exclude sensitive files
- Review code for security issues before submitting PRs
- Follow secure coding practices

## Supported Versions

We provide security updates for the following versions:

| Version | Status |
|---------|--------|
| 1.x     | Supported |
| < 1.0   | Not supported |

## Security Best Practices

1. **Dependencies**: Keep all dependencies up to date
2. **Code Review**: All code changes go through review before merging
3. **Testing**: Security-related changes should include appropriate tests
4. **Documentation**: Document any security-related changes

## Acknowledgments

We thank the security researchers and community members who help keep GlimWorld secure by responsibly disclosing vulnerabilities.
